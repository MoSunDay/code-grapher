# 2026-11-21 索引生命周期补丁

## 交付

### 索引进度与扫描安全（P0）
- `index_paths` / `index_selected` 改为先读取并 hash 过滤，`total` 只统计本次真正待解析的变更文件；
  touch/atime 等未变更事件现在发出 `total=0,files_changed=0`，不再让前端看到虚假进度；
  末帧仍满足 `done==total`
- `scan_repo` 不再吞掉子目录 `read_dir`/`DirEntry`/metadata 错误，改为带路径上下文向上传播；
  扫描失败时索引 run 直接 failed，不会在部分扫描结果上执行 `sweep_missing`，避免误删现存图谱
- `index_paths` 对 repo root 与 watcher 事件路径先尝试 canonicalize，再解析相对路径；
  兼容相对路径注册、符号链接拼写差异和已删除路径
- `finish_run` 成功路径只写一次 `runs::finish("ok")`；写失败只记录并返回错误，不再二次写 failed

### 删除 / watcher 生命周期（P1/P2）
- `spawn_watcher` 返回 `(receiver, Arc<AtomicBool>)`：调用方可停止 watcher；线程以 250ms
  `recv_timeout` 周期检查停止位，状态为停止时静默退出，不再产生 `index_failed` 噪声；
  接收端关闭导致 `tx.send` 失败时线程立即退出
- `AppState` 增加 `watcher_stops`；`spawn_repo_watcher` 注册停止位并安全替换旧 watcher，
  任务退出时按 `Arc::ptr_eq` 只清理自己的记录
- `DELETE /api/repos/{id}` 在 `cloning` 或 `indexing` 时返回 409；删除成功前先停止该仓库 watcher，
  避免删除后继续监听/派发索引任务
- clone_done 与本地注册均检查 `spawn_index_job` 返回值：clone 成功后初始索引未启动会发
  `index_failed`（run_id=null），本地注册记录明确 warning；`cloning` 锁统一使用中毒安全处理

### 前端 WS 契约（P1）
- `IndexProgressEvent` 补 `current_file`；WS union/parser 补 `repo_added`、`analyze_enqueued`、
  `config_updated`、`lagged`，不再静默丢弃服务端事件
- Dashboard progress 按 `run_id` 门控：忽略非 active run 的迟到帧；记住最近结束的 run，
  防止 done/failed 后进度“复活”；done/failed 不会误清新 run
- `IndexProgressPanel` 展示短 run id；`lagged` 事件写入日志尾部提示 WS 积压
- `docs/api.md` 补充 `lagged`、删除 409/停止 watcher 语义与 progress run 关联说明
