# 2026-11-20 修复收尾

## 交付

### 索引生命周期与 WS 链路
- `index_repo` / `index_paths` 统一 run 生命周期包装：开始即创建 run 并发首帧 progress（`done=0,total=0`）；
  成功写 `ok`，任何错误写 `failed`；任务 panic 由 server `catch_unwind` 捕获，先补记 failed 再发终态事件
- progress 语义修正：`total` 是本次**待解析的变更文件数**（不是全仓扫描数），末帧满足 `done==total`；
  `files_changed` 收敛为实际解析成功文件数（`parsed_ok`）
- API 与 watcher 共享 per-repo 单飞锁：API 冲突返回 `{run_id:null,already_running:true}`；
  watch 事件排队等待当前 run 结束，不再与 API 并发写图谱或丢事件；watcher 初始化/监听/通道关闭失败统一发 `index_failed`
- `index_paths` 增加删除清扫：watch 期间被删文件同步从 `files` 表移除（级联 symbols/edges）；
  目录创建/删除/改名通常没有逐文件事件，watcher 自动回退到增量全仓扫描，避免漏索引或残留旧文件；
  仓库根目录缺失时扫描直接报错，避免把“仓库被删”误判为空仓库并清空图谱
- WS 事件补全：`index_progress.run_id` 为真实 `index_runs.id`（旧服务端 null 由前端兼容）；
  `index_failed.run_id` 可空（失败发生在建 run 之前，如 watcher 初始化失败）；
  `index_done.stats` 增加 `symbols_total`/`edges_total`；前端按 `run_id` 关联本次 run，
  `total=0` 显示“准备中”，`already_running` 给出明确提示
